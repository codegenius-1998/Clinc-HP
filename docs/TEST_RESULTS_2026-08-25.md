## ⛔ 検出した不具合

### BUG-01：セクション画像が表示されない（重大）

**症状**：生成されたサイトの「ご挨拶」「施設案内」で、本文の上に**大きな空白**が出ます。画像ファイルが存在しないためです。

**影響範囲**：生成済み5サイト中 **3サイト**

| サイト | 欠落している画像 |
|---|---|
| clinic-mt5ogpn70x1p（りなか駅前皮フ科） | `images/greeting.jpg` `images/facility.jpg` |
| clinic-mt5noavvp8o4 | `images/greeting.jpg` `images/facility.jpg` |
| clinic-mt0rbiqnz2pb | `images/facility.jpg` |

ブラウザ上でも `naturalWidth === 0`（読み込み失敗）を確認しました。

**原因**

テンプレートの「文章＋カード」ブロックは、**カード画像とは別に、セクション自身の画像**を持っています。

```
テンプレート                        サイト生成後
_templates/xxx/images/greeting.jpg   generated/yyy/images/greeting.jpg
  ↑ 実ファイルあり                      ↑ ファイルが作られない
```

サイトを作るとき、テンプレートの内容は**丸ごとコピー**されますが、コピーされるのは**画像のパス（文字列）だけ**で、画像ファイル本体はコピーされません。

一方で画像生成は、AIが立てた計画（`plan.images`）に載っているものだけを作ります。カード画像は計画に載るのに、**セクション自身の画像は載らないことがある**ため、パスだけが残って参照切れになります。

該当箇所は [src/lib/siteGenerator.ts:301](../src/lib/siteGenerator.ts#L301) の `applyImagePaths`。コメントには

> Slots with no file … are left alone so a template's own sample image survives.
> （ファイルが無いスロットはそのままにする。テンプレート自身のサンプル画像を残すため）

とありますが、**サンプル画像の「ファイル」は新しいサイトに来ない**ため、この前提が成立していません。

**なぜ全サイトで起きないか**：AIが計画にセクション画像を含めた場合だけ正常になります。つまり**AIの出力次第で発生する**ため、再現が不安定です。

**対処案**（未実施・ご指示をお待ちします）

| 案 | 内容 | 長所 / 短所 |
|---|---|---|
| A | ヒーローやスタッフと同様に、**セクション画像も必ず生成対象に加える** | 確実。画像が数枚増えるぶん生成時間と費用が増える |
| B | 画像が無いブロックは**画像なしで描画**する | 費用ゼロ。デザインが変わる |
| C | テンプレートのサンプル画像を**サイトへ複製**する | 費用ゼロ。全サイトが同じ写真になる |

**推奨はA**です。ご挨拶と施設案内は写真があってこそ成立するセクションで、空白のまま公開するわけにはいきません。

### ✅ BUG-01 は修正済み（対処案A）— 2026-08-25

**直した内容**

1. **[siteGenerator.ts](../src/lib/siteGenerator.ts) `buildImageJobs`** — AIの計画に頼らず、**ドキュメントが参照している画像パスをすべて生成対象に加える**処理を追加しました。対象は「文章＋カード」のセクション画像とカード画像、画像バナー、ギャラリーです。すでに計画に入っているものは重複しません（スロット単位で重複排除）。**画像パスが空のブロックは対象外**なので、余計な画像は増えません。
2. **同 `applyImagePaths`** — それでもファイルが用意できなかったパスは、**残さずに空にする**よう変更しました。壊れた画像が出るくらいなら、写真なしで表示する方が安全です。
3. **[components.tsx](../src/lib/render/components.tsx)** — ロゴ・メインビジュアル・画像バナー・ギャラリーで、**画像パスが空なら `<img>` 自体を出さない**ようにしました。どんな経路をたどっても壊れた画像アイコンは出ません。

**なぜ起きていたか（確定）**

`generateSite` は生成前に出力フォルダを**まるごと削除**します。一方テンプレートからサイトを作る処理は**画像パスの文字列だけ**を引き継ぎます。つまり「テンプレートのサンプル画像が残る」という前提のコメントは**成立していませんでした**。

**検証**（AI課金なしで実施）

D1に入っている**テンプレート3件・サイト7件すべて**について、「AIが画像を1枚も計画しなかった」という**最悪のケース**を想定して照合しました。

| 対象 | 参照中の画像 | 旧仕様で保証されていなかった数 | 修正後の取りこぼし |
|---|---|---|---|
| テンプレート3件 | 各22 | 各18 | **0** |
| サイト7件 | 4〜21 | 3〜18 | **0** |

`greeting`（ご挨拶）と `facility`（施設案内）が、いずれも生成対象に入ることを確認しました。`npm run build` と型チェックも通っています。

**費用への影響**：ほぼありません。カード画像はこれまでもAIの計画に入っていたため、実際に増えるのは**1サイトあたり2枚程度**（ご挨拶・施設案内）です。

**⚠️ 既存の3サイトについて**

コードは直りましたが、**すでに作られた3サイトのファイルは欠けたまま**です。復旧には2通りあります。

| | 内容 | 費用・時間 |
|---|---|---|
| ① | **もう一度「作成」を押す**（修正後の処理で作り直す） | 課金あり・1サイト約4分 |
| ② | テンプレートの写真をコピーして応急処置 | 無料・即時。ただし3サイトとも同じ写真になる |

ご指示があれば、どちらでも対応します。
